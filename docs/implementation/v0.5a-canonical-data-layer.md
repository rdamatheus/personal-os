# Personal OS v0.5A — Canonical Data Layer

Date: 2026-09-06

## Objective

Create the persistence foundation required to finish CRUD before connecting the real AI Copilot.

The target architecture is:

```text
UI
  ↓
repository / application data service
  ↓
Supabase client
  ↓
RLS + workspace boundary
  ↓
PostgreSQL canonical state
```

The browser may later keep cache/UI state, but `localStorage` must not remain the source of truth for canonical Personal OS entities.

## Implemented in v0.5A

### Shared persistence primitives
Added `apps/web/lib/data/common.ts` with:
- `WorkspaceActor` context (`workspaceId` + authenticated `userId`);
- centralized `recordActivity()`;
- semantic archive/restore helpers;
- timestamp helper;
- required-title validation.

All repository mutations remain workspace-scoped and therefore continue to rely on the existing RLS boundary.

### Direct core repositories
Added `apps/web/lib/data/core-repository.ts` with direct Supabase operations for:
- Areas;
- Projects;
- Tasks;
- Ideas;
- Decisions;
- Routines;
- Check-ins (append/read lifecycle);
- Events (append/read lifecycle).

Mutable entities expose the intended lifecycle:

```text
create → list/read → update → archive → restore
```

Append-oriented history exposes:

```text
create → read
```

### Audit behavior
Repository creates, updates, archives and restores emit `activity_log` records where appropriate.

This establishes a consistent path for later learning/recommendation provenance:

```text
mutation → activity_log → history/context → future Copilot reasoning
```

### Soft-delete convention
Normal Personal OS lifecycle uses `archived_at` instead of destructive SQL deletion for mutable core records. This preserves history and future auditability.

### Compatibility mappings
The repository layer deliberately adapts current database naming where the domain contract is richer:
- Routine `title` maps to database `name`;
- Routine `recurrence` maps to `frequency`;
- Routine `estimatedMinutes` maps to `duration_estimate`;
- Decision `outcome` maps to database `decision`;
- current Task persistence still uses database status/energy representations until the dedicated task migration/refactor is approved by implementation sequence.

These mappings keep v0.5A non-destructive. A later migration can normalize database/domain vocabulary after real UI flows are migrated.

## What v0.5A intentionally does not claim

v0.5A is a repository foundation, not the completion of every user-facing CRUD screen.

Still transitional after this release:
- the main dashboard UI continues to use the legacy browser store for Tasks, Projects and Decisions;
- the old `core-cloud-store.ts` synchronization bridge remains temporarily active so the current UI is not broken mid-migration;
- Ideas, Routines, Check-ins and Events are not yet wired from the main dashboard to the new repositories;
- Journal still uses its independent browser store;
- Goals/Routes currently use their existing direct data service and will be consolidated with the repository conventions in their dedicated pass;
- no AI model or AI Edge Function is connected yet.

The bridge is now considered **deprecated compatibility infrastructure**. New feature work must use the canonical repository layer rather than adding more `localStorage` synchronization.

## Next implementation pass — v0.5B

Migrate the highest-value execution flow to direct repositories:

1. Tasks UI → direct Task repository;
2. Projects UI → direct Project repository;
3. Goals UI → complete update/archive/restore lifecycle;
4. remove Tasks/Projects/Decisions from the polling sync bridge once their direct migration is validated;
5. ensure each mutation is reflected in `activity_log`;
6. validate persistence across two browsers/devices;
7. rerun build and tenant isolation checks.

## Definition of done for the pre-AI persistence program

The database is the canonical source of truth for all persistent Personal OS modules, and a fresh authenticated browser can reconstruct the user's state without relying on previous local browser storage.
