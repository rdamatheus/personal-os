# Personal OS v0.6 — Jornadas & Progressão

Date: 2026-09-07

## Objective

Introduce the first real gamification/progression experience in the application, using the Big Ambitions research as a design reference without copying its UI, story, names, or assets.

The experience translates canonical Personal OS data into a progression language:

```text
Goal        → Journey
Route       → Chapter
Route Step  → Mission
```

No duplicate persistence model was added. Supabase remains canonical through the existing Goal / Route / RouteStep entities.

## Implemented

### `/jornadas/`

New authenticated page with:

- journey dashboard;
- journey count;
- average progress;
- completed mission count;
- next mission;
- journey creation by goal archetype;
- current-state capture;
- success-definition capture;
- target date;
- starter ambitions;
- chapter map;
- mission completion;
- visual chapter locking;
- real-progress principles.

### Journey archetypes

The page uses the existing progression frameworks:

- acquire;
- learn;
- build;
- improve;
- stabilize;
- decide;
- experience;
- habit;
- financial;
- career/business;
- custom.

Each archetype now has a reusable chapter/mission template in:

`apps/web/lib/progression/journey-runtime.ts`

These templates are scaffolds. They are not presented as universal advice. A later AI pass will adapt them to the person's context, resources, constraints and researched evidence.

## Progression semantics

The application treats chapter progression as:

```text
current chapter
→ complete real missions
→ chapter reaches 100%
→ next chapter becomes visually available
```

Future chapters may already exist canonically as Routes, but the Journey UI keeps them visually locked until the previous chapter is complete. This avoids adding another database state only for gamification.

## Creation flow

When the user creates a Journey:

1. create a canonical Goal;
2. select a progression archetype;
3. generate chapter scaffolding from the archetype;
4. persist each chapter as a Route linked to the Goal;
5. persist each mission as a RouteStep;
6. use standard route progress recalculation as missions are completed.

## Design principles

- real-world progress before fake XP;
- no punishment for missed tasks;
- user defines success;
- chapters unlock because of meaningful prerequisites;
- capability growth matters more than clicks;
- the route can later be recalculated instead of treating failure as game-over;
- AI proposes/adapts, but persistent changes require user control.

## Deliberate limitations of v0.6

- AI is not yet generating personalized journeys;
- chapter dependencies are visual/derived, not a dedicated DB relationship;
- route templates are archetype-based and generic;
- real progress metrics such as money saved, skill repetitions, revenue and asset acquisition are not yet first-class metric records;
- no XP/level system is implemented yet;
- no task/routine/project conversion from missions yet;
- no automatic route recalculation yet.

## Next slices

1. add explicit journey metrics and evidence;
2. route-step → Task / Routine / Project conversion;
3. deterministic Next Best Action across journey missions and canonical tasks;
4. persistent milestone/capability unlock model;
5. secure AI Journey generator using the progression contract;
6. researched route sources/provenance;
7. adaptive route recalculation after changes in money, time, energy or constraints;
8. optional visual XP/levels derived only from verified real progress.
